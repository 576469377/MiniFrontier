# 在浏览器中比较实验检查点

[返回操作指南](README.md) · [实验档案](../experiments.md) · [当前训练安排](../pretraining-plan.md)

实验浏览器支持六个版本的文本生成：MiniKimi-K3、MiniQwen4、MiniDeepSeek-V4 / V4.1 和 MF1.0 / 1.1，可以比较不同实验或保存时刻的输出。两版 MF1 的图片与视频输入使用下方的[独立媒体 Demo](#mf1-图片与视频)。两种入口都需要本地已有检查点。

## 启动实验浏览器

```bash
uv run minifrontier demo --root outputs --device cpu --include-experiments --port 7860
```

浏览器打开 `http://127.0.0.1:7860`。`--root` 指向训练输出根目录；默认打开正式训练视图，展示已保存的 `strategy` 检查点；这些权重仍可能未通过能力验收。`--include-experiments` 另行开放短程诊断和历史实验范围；已验收视图单独筛选通过验收且绑定该版本的权重。

| 设备选择 | 参数 |
|---|---|
| CPU | `--device cpu` |
| 按 `nvidia-smi` 的物理卡号选择 | `--gpu 0` |
| 按 `CUDA_VISIBLE_DEVICES` 映射后的可见编号选择 | `--device cuda:0` |

`--gpu` 与 `--device` 互斥。Demo 单卡运行；在训练主机上使用 GPU 时，选择有足够显存的空闲设备。CPU 示例也需要容纳所选模型及检查点加载时的内存。

用 `--experiment-root my-experiment` 可将 `outputs/my-experiment/` 下的诊断任务列为本轮实验，其余诊断任务归入历史实验。该参数需与 `--include-experiments` 一起使用，可以重复，目录必须位于 `--root` 内；不指定时实验视图展示全部诊断检查点。正式训练视图单独列出 `strategy` 运行。

## 选择权重与输入

1. 按模型和实验范围筛选，选择一个已保存的检查点，核对阶段、step、保存时间和训练量。尚未首次保存的运行不会出现。
2. 选择文本续写或对话模式。预训练权重默认续写；SFT 等阶段默认使用对话模板，也可手动切换。
3. 输入固定提示，设置生成长度、Temperature、Top-p 和随机种子。首次比较可保留默认的 `Temperature=0`、`Top-p=1`、`seed=0`。
4. 生成后核对记录中的实际载入版本、输入、参数和输出，再切换检查点重复同一提示。

列表刷新只读取元数据与文件身份，生成时才载入所选权重。如果训练恰好保存了新版本，页面会要求重新确认，避免将新权重的回答标成旧版本结果。保存时的状态与训练日志可能不同步；“预算完成”或 `budget_complete_unqualified` 只表示这次运行达到预算。

MF1 分别显示本阶段和累计主预训练 CE。跨阶段比较时，使用累计主 CE；判断该阶段预算消耗时，使用本阶段计数。

`Temperature=0` 使用贪心解码，Top-p 和 seed 不影响 token 选择；采样需将 Temperature 设为正数。固定参数有助于比较，但不能消除欠训练模型的重复或空输出。MF1.0 / 1.1、V4 / V4.1 使用各自的权重和配置，不能通过修改模型名称混用。

## 阅读和比较生成记录

本页保留最近 20 条生成记录，包含当次检查点、提示词、输入模式、生成参数、实际输出和耗时。空输出也保留，便于观察模型是否立即结束。

- 同一提示比较不同检查点时，保持输入模式、长度和采样参数一致；生成记录中的参数不会跟随后续表单修改。
- 选中两条记录进行并排比较。加载时间与生成时间分别显示，避免把读取权重的耗时当成生成速度。
- 用“导出 JSON”保存本页记录，供后续复核；刷新或关闭页面前先导出需要保留的结果。

V4.1 当前生成路径每步重算完整前缀，长输出的耗时会增加；其 cache 接口尚不提供增量 KV 加速。比较延迟时需同时记录架构、输入长度和生成长度。

这些是定向生成观察。语言、算术或视觉能力仍需独立任务与固定评价集，历史失败和测量条件见[实验档案](../experiments.md)。

## MF1 图片与视频

准备好 MF1.0 或 MF1.1 检查点或导出文件后启动，页面会显示实际模型版本：

```bash
uv run minifrontier mf1 demo --checkpoint outputs/mf1-export/model.pt \
  --device cpu --port 7861 --allow-unqualified
```

导出方法见 [MF1 指南](minifrontier1.md#导出和诊断-demo)。打开 `http://127.0.0.1:7861`，添加图片或视频，在对话模式下选择 direct/thinking 并设置生成预算；纯文本也可使用续写模式。

先检查输入预算，页面会显示实际图像尺寸、采样帧和视觉 token 占用，再执行生成。修改提示、媒体或参数后须重新检查；视频由浏览器抽帧，模型只处理列出的帧。

此入口在启动时加载并绑定一个检查点，详情和生成记录显示该版本。磁盘上的文件随后被替换不会更新内存中的模型；切换权重需重新启动并刷新页面。

实验浏览器的生成请求串行执行，单次完成后释放加载的权重与 CUDA 缓存；独立 MF1 媒体 Demo 持续保留启动时的模型。两者均不更新训练权重或改写训练状态。
