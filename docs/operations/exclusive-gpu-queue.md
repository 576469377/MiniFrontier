# 单卡独占实验队列

> 本页说明队列机制；下方具体配方衔接为当时的安排。当前实验选择与停止原因见[总计划](../experiments/current-plan.md)，登记和暂停操作见[实验管理](experiment-management.md)。

2026-09-10 起，后续实验采用一个任务使用一张物理 GPU、每张 GPU 同时最多一个项目任务的调度方式。各机器运行各自的队列，机器之间传输已冻结的数据和源码，不使用跨机器 DDP。

显存够用并不代表同时运行两个训练任务能提高效率。它们仍可能争用算力、显存带宽、CPU 和数据读取；利用率瞬时为零也不能证明任务已经退出。新的调度器同时检查 GPU 计算进程、实际空闲显存和设备锁。

## 运行入口

在 Git checkout 中准备并冻结队列 JSON，再运行：

```bash
python -m scripts.run_exclusive_gpu_queue --plan /path/to/queue-plan.json
```

计划记录 `workspace`、`allowed_gpu_ids`、`controller_sha256` 和 `main_budget_eligible: false`。每项任务记录唯一 `id`、`output`、`command`、`source_root`、`source`、`inputs` 的 SHA-256，以及 `memory_gib` 和 `reserve_gib`。命令参数 `{gpu}` 在启动时替换为物理编号，`CUDA_VISIBLE_DEVICES` 使用对应 GPU UUID。各主机可以使用不同数量的卡，编号从 0 开始。

队列按顺序等待前置结果及可用 GPU。设备锁在创建 CUDA 上下文之前取得，并由启动的工作进程继承。调度器退出不会终止训练；以相同计划重启时，通过 PID 与启动时间识别原进程，避免重复启动。已有输出不会被覆盖，失败任务需检查原因后显式恢复。

开始任务前要求磁盘至少有 66 GiB 空间，其中 50 GiB 保留给现有产物及写入余量；训练过程仍执行各训练器的磁盘保护。显存准入要求为任务预计用量加 1 GiB 上下文余量和声明的设备保留量。多个任务启动后立即登记设备占用，不能在下一次 `nvidia-smi` 更新前挤到同一张卡。

只有明确核实为遗留占用的上下文，才可以在本机计划中按 GPU UUID 和宿主 PID 精确登记例外。例外仍按实际剩余显存判断，其他新进程不能继承豁免。宿主 PID 不用于对容器内进程发送信号。

## 配方与历史衔接

- 已经开始的实验继续使用原源码、数据顺序和 token 账本。历史双卡对照完成后释放设备，后续任务使用单卡。
- 旧的双任务共享队列入口已停用；保留其实现和历史记录用于复盘。
- Qwen 的单卡学习率对照保持 20M CE、16384 输入 token 的全局批次及原始初始化。它们与已有双卡试验属于独立运行。
- Kimi 和 DeepSeek 的后续种子复验分别采用当前候选学习率，改变随机种子以检查结果是否稳定。少量种子的结果仍不足以证明最终配方最优。
- MF1 的扩展指令试验仍须通过原控制集门槛：32 条训练语言题至少 29 条正确、至少 30 条输出 EOS，32 条保留视觉题至少 28 条正确。未通过则记为 `needs_diagnosis`。
- MF1 的合成性能测试单独记录；吞吐结果不计入正式训练 token，也不代表模型能力。

远端迁移应保存文件传输校验值、原始和新数据清单的对应关系、运行环境版本与命令。原始训练数据清单及媒体记录里的绝对路径可以按主机重定位；使用 `scripts/relocate_native_media.py` 重建媒体行的字节索引，并记录清单、媒体文件和索引修改前后的 SHA-256。文本、样本身份、图像、token ID、标签和 tokenizer 保持一致。

主机地址、用户目录、PID 和设备 UUID 仅保存在忽略的本地运维产物中。公开实验档案使用主机标签及归一化路径。所有这些试验仍是训练配方验证，完成队列不会自动开启正式 PT、SFT 或 RL。
