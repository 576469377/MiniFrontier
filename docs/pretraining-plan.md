# MiniFrontier 数据与四模型预训练主计划

更新：2026-09-10。**这是本轮执行计划的唯一入口。** 数据、四模型配方、阶段预算、从零初始化、验收、存储与记录规则均在本文件维护；历史修订不再作为补充执行指令。

目标：**整理并关闭已有实验 → 构造正式预训练数据 → 完成四个 base 模型。** 总主训练预算 10.5B（105 亿）有效 CE token，索引器另计。四个正式首阶段从随机初始化开始；SFT/RL、教师、蒸馏、draft、QAT 和完整架构消融放到 base 交付之后。

本文件给出执行目标，不把计划预算写成完成进度。实验结果与运行状态使用现有台账；数据/配方/阶段资格以绑定实际产物的验收记录为准。

## 1. 执行顺序与待办

按下面的顺序推进；数据处理与配方定案可以并行，某个模型满足条件即可开始，不等待其他模型的无关事项。先核对并复用已有合格证据，不能因整理计划而把已完成的验证再做一遍。

| 顺序 | 任务 | 完成时必须有的产物 | 后续依赖 |
|---|---|---|---|
| A1 | 关闭旧实验与悬空队列 | 现有台账的结论、限制、处置；停止自动派生探索 | 所有正式主线 |
| A2 | 四模型逐一冻结配方 | 每模型完整运行配置、数据/模型版本、batch/LR/日程及阶段状态继承表 | 对应模型首阶段 |
| B1 | 首批正式数据 | 约 0.5B 去重文本库存、首阶段所需媒体、来源/划分/质量报告、冻结 tokenizer、可消费 shard | 对应模型首阶段 |
| B2 | 补充后续数据 | 按 1.5B、约 5B 候选池逐步供给；长度与媒体覆盖、重复率和磁盘账本 | 对应后续阶段 |
| C1 | 首阶段生产准入 | 最终 batch 与真实媒体配置的正确性、恢复、吞吐/显存及空间验收 | 对应模型正式第 0 步 |
| C2 | 从零启动 K1/Q1/D1/P0 | 新目录、随机初始化、冻结配方、完整训练记录 | 各自后续阶段 |
| C3 | 完成主训练与转换 | 下表预算、索引器/稀疏转换、长上下文与固定效果评估 | 四个 base 交付 |

**工作参数已选择，最终配方尚未冻结**：见[工作参数与依据](experiments/2026-09-10-pretraining-cutover/working-recipes.md)及机器记录的 `training_recipe`。Kimi/DeepSeek 使用 32K、Qwen/MF1 使用 16K 全局 input 目标，各自 LR 与主日程已选；正式数据/tokenizer、长度消费、真实媒体 microbatch、生产资格及实际父权重的阶段验收仍待绑定。这不构成自动实验队列。

## 2. 数据构造方案

### 2.1 共享语料池与来源

建立一个共享、可追溯的 canonical 语料池，候选规模为 **约 5B 文本 token**。用指定参考 tokenizer 计候选量；各模型预算以自身实际 CE 计数，不假设同一段原文在不同 tokenizer 下等长。四模型总训练量不是四份物理拷贝。

| 领域 | 首选来源/构造方向 | 接入要求 |
|---|---|---|
| 中文通用/教育 | 现有 opencsg/Fineweb-Edu-Chinese-V2.1 | 固定 revision、分片/分数条件，保留 source 字段；分层抽查，排除低质混入。[数据卡](https://huggingface.co/datasets/opencsg/Fineweb-Edu-Chinese-V2.1) |
| 英文教育 | FineWeb-Edu；需要时使用其去重子集 | 固定文件/行组采样，跨来源去重；数据卡为 ODC-BY 并列明 Common Crawl 条款。[数据卡](https://huggingface.co/datasets/HuggingFaceFW/fineweb-edu) |
| 代码 | Python-Edu/The Stack v2 中可以核验来源的内容；补充 CodeParrot 的逐文件许可候选 | 补齐 repo/blob/license 信息；CodeParrot 只保留开头明确许可声明与 license 字段一致的文件，固定数据版本与内容 hash，原仓库 commit 缺项单列。不能因聚合数据卡的标签而忽略具体代码来源。[Python-Edu](https://huggingface.co/datasets/HuggingFaceTB/smollm-corpus)、[The Stack v2](https://huggingface.co/datasets/bigcode/the-stack-v2)、[CodeParrot train](https://huggingface.co/datasets/codeparrot/codeparrot-clean-train) |
| 数学/科学 | OpenWebMath、带来源的解释性文本、项目可验证生成器 | 不让有限算术模板占满此域；留出生成规则/模板组合而不只是随机种子。[OpenWebMath](https://huggingface.co/datasets/open-web-math/open-web-math) |
| 对话/结构化文本 | 现有已核验对话来源、JSON/表格/工具文档等 | 此处用于预训练混合；与后续 assistant-only SFT 集分开 |
| 图像/文档/图表/VQA | FineVision/Cauldron 的逐项准入子集、合法来源的 caption、项目生成 OCR/图表 | 逐子集记录条款；一个总数据卡不能覆盖所有来源。[Cauldron 说明](https://huggingface.co/datasets/HuggingFaceM4/the_cauldron) |
| 视频 | 已确认来源的短视频及可验证时序生成样本 | 保存原视频身份、时间戳、采帧规则、分辨率与内容校验，不只保存帧序号 |

这些是选定接入方向，不是已经下载或通过验收的声明。旧 96 张图片、MF1 色块和 32 条问答属于诊断集，不能充当正式视觉/语言主体。NC 数据保留清晰实验用途和权重发布限制；不把项目代码 Apache-2.0 写成训练数据或模型权重的统一许可。

正文中的来源核查是数据构造的实际交付内容，不要求先完成一个漫无边际的法务/数据研究项目。来源缺项进入隔离清单，先使用已通过的来源；不得静默用重复数据填补缺失领域比例。

### 2.2 清洗、划分与验收

1. **来源冻结**：dataset/revision/config/files、采样 seed、原文/媒体 ID、校验值和条件；流式读取选中分片，拒绝全库下载。
2. **规范化**：编码、HTML/模板噪声、语言、极端长度、乱码、重复段落、代码解析与媒体可解码检查。保留原文到规范化样本映射。
3. **去重和划分**：先按文档/仓库/原图/视频/同源多问答分组；精确和近重复去重后，以组分 train 98.5%、val 0.5%、test 1%。不能逐行随机把同图问答拆开。
4. **污染核查**：按已选验证与 benchmark 的原始样本/衍生身份过滤；保留匹配规则和剔除数量，test 封存，不用于反复挑配方。
5. **人工抽查一次**：每个主要来源/领域至少 100 条，图像/视频按任务分层；记录可读性、标签是否对应媒体、来源缺项和异常率。出现实质问题时定向修复，不反复重审已固定的来源。
6. **tokenizer 与编码**：只用训练划分，冻结词表/控制 token；检查中英文/代码切分、round-trip、越界 token、文档边界、loss mask、媒体 span 和截断。32K/64K 不直接横比 token NLL。
7. **manifest 准入**：每域独立文档/媒体量、可用 token、计划消费量、曝光与重复率、文件大小、哈希、验证集合、处理代码版本均明确后，才标 formal_admission=true。

交付文件以正式 data manifest 为索引，至少包含 source_allowlist、split manifest、质量报告、去重/污染报告、tokenizer 报告、按阶段混合表、数据账本和存储账本。不要仅将原配置的 not_prepared 改成 prepared。

首版文本污染核查固定 [HumanEval](https://github.com/openai/human-eval)、[MBPP](https://github.com/google-research/google-research/tree/master/mbpp) 和 [GSM8K](https://github.com/openai/grade-school-math) 的来源版本与原始文件 hash。其所有分区均排除于本轮训练，公开测试部分留作阶段末/最终评价；日常配方判断使用独立语料验证集。匹配使用规范化题干、至少 64 字符的 13 词连续片段及源仓库身份，并剔除命中的完整相连组；这不证明已排除所有转述、翻译或视觉污染。规则与清单由 `minifrontier.data.evaluation` 产生，原题/答案不进入源码包。

共享文本合并复用已有去重索引，补充跨切片去重并保留历史重复别名。各输入已留出的验证/测试组保持留出；组相连时 test 优先于 val，不将旧留出样本重新放入训练。合并输出仍为候选，先报告实际训练库存、剔除量和分层抽查样本，再完成质量与 tokenizer 准入。

### 2.3 各模型数据比例与供给批次

下表按各模型**文本子集的 CE**计比例；视觉另立账本，不混用 sample 比例与 CE 比例。

| 模型 | 中文 | 英文 | 代码 | 数学/科学 | 对话/结构化 |
|---|---:|---:|---:|---:|---:|
| Kimi | 45% | 25% | 15% | 10% | 5% 对话 |
| Qwen | 40% | 25% | 20% | 10% | 5% 对话 |
| DeepSeek | 40% | 25% | 20% | 10% | 5% 对话 |
| MF1 | 42% | 28% | 12% | 10% | 8% 结构化 |

来源不足时记录领域缺口和阶段延后，不自动提高简单生成样本重复率。每个来源/模板的曝光倍率预先声明，日报同时给独立量与消费量。

首轮共享文本库存按参考 tokenizer 准备至少 **0.5B 个去重训练 token**，各模型的第一个生产阶段必须有足量、匹配领域比例的可用 token；这是交付切片，不是新增 0.5B 小实验。随后按 1.5B、约 5B 的候选池规模补齐后续阶段；已准入 shard 的内容不可原地替换。

视觉保留原计划规模：MF1 候选 **1.5M 独立图片、5M 图片曝光、120K 视频曝光**；实际视频独立数另报。前三者绝不可混称为“训练了几百万张不同图片”。Kimi/Qwen 共用底层媒体文件，但各自保留处理器、模态位置和采样账本。自然图片、OCR/文档、图表、多图必须都有独立留出；生成色块仅用于回归检查。

不要求一次将 1.5M 图片全部落在 175。本地使用有界媒体 shard 缓存，固定远端 revision 与哈希；持续预取下一分片。不可把可训练的随机视觉塔输出预先缓存成固定 embedding 来节省空间，那会改变原生视觉训练目标。

### 2.4 数据加载与缓存验收

- 三个来源模型已有 memmap 数据路径，优先复用；无需再造一套通用加载器。
- MF1 必须验收二进制 shard 的训练消费、批量合并和多模态边界。已有实现先核对当前产物，缺口再补齐；避免正式训练继续按记录重复读取、验证和编码 JSONL。
- 旧 MF1 编码格式中 ids/labels/三轴 positions 至少 **18 bytes/input token**，尚未算 JSON 索引。5B 全量编码约 83.8GiB；正式预算按最终实际格式核算，不能只按 uint16 的 2 bytes/token 估空间。
- 采用按需 shard：纯文本只保留紧凑 token 流、文档边界和必要 mask，position 可按确定规则恢复；媒体只保存必要的稀疏元数据。压缩前后对同一批样本验证 token、labels、位置和模型输出。
- uint16 需确认最大 token ID≤65535，包含所有新增控制 token；否则采用 uint32。不能静默截断。
- 每条主线保存 shard/cursor、shuffle/采样 RNG、混合累计账本、媒体重复与数据版本，恢复后不重新从首个 shard 开始。

## 3. 四模型配方与训练阶段

### 3.1 主预算与阶段顺序

阶段预算沿用四份模型专项策略。四模型主训练共 **10.5B CE**；indexer 的 input token 另计。

| 模型 | 生产阶段顺序 | 主 CE 总量 | indexer 另计 |
|---|---|---:|---:|
| Kimi | K1 0.2B → K2 1.2B → K3 0.4B → K4 0.2B | **2B** | 无独立稀疏 indexer 阶段 |
| Qwen | Q1 0.3B → Q2 1.2B → Q3 indexer → Q4 1B → Q5 0.5B | **3B** | Q3 20–60M input；首版按 20M 排期，是否增量按预置 indexer 指标判断 |
| DeepSeek | D1 0.25B → D2 0.5B → D3 indexer → D4 1.5B → D5 0.25B | **2.5B 文本** | D3 10–30M input；首版按 10M 排期 |
| MF1 | P0 0.2B → P1 0.8B → indexer → P2 1.4B → P3 0.6B | **3B** | 40M input |

这里的 DeepSeek 交付为现有文本主配置；项目 Vision-Exp 是后续扩展，不能说它在本轮文本预训练中已经学过图像。其 V1 10–30M CE warmup、V2 240M、V3 60M 保留在专项策略；在四个 base 主目标后再推进，另列预算和参数量。

### 3.2 配方基线、候选和冻结条件

下表区分模型专项方案与本地 pilot 候选。只冻结一个用于本轮的工作配方；不要求找出理论最优，也不把旧实验数值直接升级为正式值。M 为百万、B 为十亿；batch 是全局非 padding input 目标，CE 是实际参与主语言损失的预测位置。

| 模型 | 规模参考 | batch / 优化器与 LR | 日程与定案事项 |
|---|---:|---|---|
| MiniKimi-K3 | 约 204.5M，原生视觉/MTP | 工作值固定 32K；kimi_muon 原始 LR 0.005，Adam 分支 3e-4 | 整条 2B 主 CE：20M warmup，随后 cosine 到 0.1 peak；数据/资源绑定未完成 |
| MiniQwen4 | 约 513.4M，原生视觉/MTP | 工作值固定 16K；qwen_muon LR 0.01、Adam 3e-4 | Q1/Q2 前 15M warmup 后保持；Q4 主干取 0.4 倍 peak、5M warmup，Q5 的 500M 冷却；indexer 另列 |
| MiniDeepSeek-V4 | 约 244.0M 浮点参数，文本 | 工作值固定 32K；主干 deepseek_muon 两分支共用 LR 3e-4 | 25M warmup，保持到累计 2B，最后 500M cosine；首版不使用未定案 ramp；indexer 独立 Adam 分组 |
| MiniFrontier1.0 | 约 228.2M，原生视觉/MTP | 现有基线：16K、AdamW；主干 peak 3e-4，视觉与标量 1e-4；microbatch 按实际媒体测定 | 前 2M 主 CE warmup，至累计 2.4B 保持 peak，最后 600M cosine 到 0.1 peak；indexer 独立日程 |

参数量来自既有配置核查，正式冻结时按最终 config 重新统计。MF1 的 1.5e-4 是旧诊断候选，不是当前已选正式默认。

- Kimi 按其 Muon 分组与归一化定义记录原始 LR，不能与 DeepSeek 的同名数值直接横比。正式若采用整条 2B 的 1% warmup，才对应 20M；需同时验证跨阶段主 CE 日程实现。
- Qwen Q4 的主干 LR 按专项方案从 Q2 稳定 peak 的 0.3–0.5 倍与短 warmup 起步，indexer 分组独立；不能用“全模型全程不重启 LR”覆盖。
- DeepSeek 当前 --lr 控制 Muon/Adam 两分支，--muon-lr 不生效。D5 的 MTP 按专项方案由 0.3 降到 0.1，阶段变更必须显式记录。
- MF1 默认 AdamW betas=(0.9,0.95)、eps=1e-8、clip=1.0；主干/视觉 WD=0.1、embedding/head/lookup WD=0.01、标量 WD=0。最终逐参数组文件与实际运行核对。
- 三个来源模型保留 64K、MF1 保留 32K 作为当前词表容量基线。完成正式训练划分上的质量检查及既有词表候选的闭环后，冻结实际映射/hash；同一词表大小不代表编码可共享。

上述工作参数的旧数据依据、算法分组、逐阶段 peak、生产资格输入上界和未验证部分记录在[工作配方](experiments/2026-09-10-pretraining-cutover/working-recipes.md)。32K 是基于候选范围作出的工程选择，没有把其他 batch 的结果改称一次 32K 质量试验；不据此恢复全排列探索。

冻结记录需有 config/hash、seed、tokenizer/hash、数据/媒体混合、逐参数组优化器/LR、input batch、microbatch、累计规则、MTP、完整预算/日程以及第 4 节状态继承表。补充验证确有必要时，先登记问题、有限候选、token/GPU 小时预算及停止条件，不能恢复全排列队列。

### 3.3 MiniKimi-K3

- K1 长度 512→1024，约 200K 图像曝光；K2 1024→2048，约 1.2M 图像/20K 视频；K3 2048→4096，约 500K 图像/10K 视频；K4 混合长度、较高质量数据，约 100K 图像。
- 原生 MoonViT 随阶段训练，保持文本与视觉参数组的 LR、梯度与曝光记录。
- 路由/AttnRes/KDA 指标作为健康监测；不为达到漂亮的专家均匀曲线反复换配方。
- 进入更长阶段要求真实长文和位置覆盖，拼接短样本的总长度不能当长上下文学习。

### 3.4 MiniQwen4

- Q1/Q2 使用 dense_pretrain；Q3 冻结合格 dense teacher，仅训练声明的 indexer；Q4/Q5 才使用 sparse_cpt。
- 媒体曝光依次约 300K、1.2M、800K、200K，视频在 Q2/Q4/Q5 分别约 20K/20K/10K；图像数是曝光，独立数必须另报。
- Q3 的前置条件在 Q2 结束时处理，无需在 Q1 前训练完整 indexer。保存 teacher 对应权重、索引目标、有效 query 数及梯度范围。
- dense→sparse 以同一权重、同一数据比较；建议本地验收阈值为语言域 NLL 相对退化≤2%、固定视觉指标下降≤3 个百分点，达不到时只修复/延长该转换，不重跑 Q1/Q2。

### 3.5 MiniDeepSeek-V4

- D1/D2 先建立文本基础，D3 进行 indexer 训练，D4/D5 做稀疏继续预训练及收尾。
- compression ratio、Hash/MoE、mHC 和 MTP 按冻结结构保留；监控梯度、路由与有效压缩窗口。
- 没有视觉的阶段不凭空计算媒体预算；未来接 Vision-Exp 先验证原文本模型输出保持，再做视觉 warmup 与联合训练。
- 固定 batch 与预先声明的 batch ramp 保留为原计划候选，在正式 D1 前定案。选定 ramp 后从第 0 步写入完整 schedule，后续按 CE 节点变更，不在各节点随机重启；不把 pilot 的增长节点直接冒称正式或官方参数。

### 3.6 MiniFrontier1.0

- 保留既定 228M 结构，先修复执行与数据路径，不在该时间盒内新增组件。
- P0/P1/P2 的视觉 CE 占 20%，P3 占 25%；3B 中共 **630M 视觉 CE、2.37B 文本 CE**。视觉 feature token、媒体曝光和视觉文本 CE 分开计数。
- 原生随机视觉从 P0 就参与；不能把纯文本预训练完成当作 MF1 整体预训练完成。
- P0 长度 512/1024，P1 1024/2048，P2 2048/4096，P3 2048/4096/8192；P3 的 8K 需要真实训练和评估通过，OOM 或未实现时明确阶段未完成，不能降成 2K 后继续宣称 8K 完成。
- indexer 插在 P1 与 P2 之间；P2 保留当前代码的严格门槛：text/code/OCR/video 各域有效注意力质量捕获至少 90%，相对 NLL 增量≤1%，视觉准确率下降≤2 个百分点，且评估文件必须绑定实际父检查点；不采用 Qwen 表里的宽松示例覆盖 MF1 门槛。标准单轮和媒体协议可验证后先训练，thinking/RL 不作为前置条件。
- 执行性能按最新真实混合数据结果验收；未通过时只处理对应工程问题，不继续慢速语言诊断链。

## 4. 初始化、恢复与阶段转换

| 场景 | 模型权重 | 优化器、数据位置与计数 | 执行规则 |
|---|---|---|---|
| 正式首阶段 K1/Q1/D1/P0 | **随机初始化**，含随机视觉模块 | 按冻结 seed/config 从零建立 | 新输出目录，init=null、resume=null；不继承旧 pilot、诊断、batch、SFT 或性能验收权重 |
| 同一正式运行中断恢复 | 本运行的恢复检查点 | 恢复 optimizer、sampler/RNG、router、token ledger 等全部状态 | 配方/数据/tokenizer/source/预算匹配后 exact resume |
| 正式阶段转换 | 前一正式阶段的合格 checkpoint | 逐项声明继承、暂停、重置及理由 | 绑定真实父权重/hash，遵守模型专项策略，不能将普通 --init 称作完整恢复 |
| 预先设计的 batch ramp | 同一正式运行内持续学习 | 使用原完整 schedule 和累计 CE | 到预定节点改变目标 batch；不在每个节点随机重启 |

正式运行的 20M/50M/100M 存盘点只用于观测和恢复，不能先启动一个 20M 预算作业、结束后改成 2B 再称精确续训。硬件验收与旧实验的消耗单列，不补计正式主 CE。

当前严格恢复校验包含 batch、microbatch、LR、日程、总预算、数据/tokenizer 等；不删除校验字段绕过。仅改变 microbatch 在保持样本窗口与归一化时可能是执行调整，但支持兼容迁移需要专门验证，本轮不默认放宽接口。

三个来源模型的普通 --init 会新建 optimizer 与当前运行 ledger。显式 `--pretraining-program / --pretraining-phase / --schedule program` 路径已增加累计主 CE 与按参数名继承状态：主干 moments 跨 indexer 暂存、router/RNG 继承、相同数据/长度/混合与游标形状时继承 sampler；变化时记录重建。Qwen 的稀疏阶段 LR 重启属于预先声明的日程，仍保留主状态。该工程实现不代替实际父权重的质量门槛。MF1 继续使用已有 P0→P1→indexer→P2→P3 连续路径。

每次阶段转换记录 model / optimizer / router / main CE / phase CE / sampler / RNG 的处理；同阶段恢复和跨阶段迁移使用不同记录。后续阶段继承本轮已经学到的权重，不逐阶段重新随机训练。

## 5. 训练准入与效果验收

### 5.1 首阶段准入

每模型逐一满足以下条件后进入正式第 0 步：

1. 模型/tokenizer、loss 与媒体标签、因果/样本边界、梯度正确性有当前有效证据。
2. 完整配方已冻结；首阶段正式数据已通过准入并可持续供给。
3. 最终真实配置通过有限损失/梯度、CE 归一化、精确恢复，以及首阶段最大长度/媒体内存边界验证。
4. 一张可用独占 GPU、至少约 2GiB 显存余量、磁盘写入预约和恢复点保存条件。
5. 输出目录、source/config/data manifest、实际产物绑定的资格记录齐全；既有门槛未因整理计划而失效或被绕过。

### 5.2 只让相关问题阻挡相关阶段

| 问题 | 阻挡范围 |
|---|---|
| loss mask、CE 归一化、因果/样本边界、媒体标签、梯度、数据恢复错误 | 必须修复，阻挡对应模型主训练 |
| MF1 正式混合数据的执行吞吐/内存未验收 | 阻挡 MF1 大预算，其他三模型照常推进 |
| 生产 batch/LR/日程未定案，或拟采用的阶段状态继承未实现 | 阻挡对应模型/阶段；不得靠普通 --init 隐藏重置后宣称连续恢复 |
| 多轮生成历史截断 | 修复后才能使用多轮生成指标/SFT；单文档预训练无需等待 |
| thinking/final 与奖励协议 | 后训练前修复；不阻挡无 thinking 的 base 预训练 |
| 多图预算分配 | 多图阶段准入前修复；首阶段明确单图时可先推进 |
| cache 数值不一致 | 推理/相关生成评估前解决；使用已验证完整前向的 teacher-forced 验证可先开展 |
| Qwen/DeepSeek/MF1 indexer 训练与稀疏转换 | 在各自 dense→indexer→sparse 边界验证，不提前阻塞 dense 主训练 |

### 5.3 效果验证、停止与交付

- 训练日志按固定窗口统计 NLL、梯度、每域 CE、媒体曝光、吞吐与显存；损失比较使用相同领域/相同验证集。
- 首 100M 每 10M CE 做一次中等规模固定验证；之后每 50M；阶段末完整验证。定期验证约 1M CE，阶段末约 5M CE。实际评估耗时控制在训练总时间约 5% 内，变更频率必须记录。
- 图片/视频按独立原始媒体分组留出；正式视觉评价至少 1,000 个独立组，包含正常、错配、置黑与必要的时序置换。色块指标仅占回归小部分。
- 固定生成集分成自然文本续写、阅读/复制、算术/代码、视觉；对基础预训练模型不以“会遵循聊天模板”作为唯一放行条件。SFT 诊断权重与 base 权重分开。
- 同一 tokenizer 内看域 NLL；跨 tokenizer 采用固定原文的 byte 归一化损失及实际能力任务。不同模型不能凭 token NLL 高低宣布架构优劣。
- NaN/Inf、标签/边界错误、数据损坏、磁盘/显存越界立即停止对应任务，保留最近可恢复点。
- warmup 后，若同一固定验证集连续三次显著恶化（建议相对上升≥5%，并排除数据混合和统计波动），暂停该运行，检查数据/优化器/实现；不临时换目标或自动开参数网格。
- indexer 和长上下文转换的失败只阻挡下一阶段。没有完成预算及阶段验收就标 incomplete/blocked，不用“训练完了”替代。

最终每个模型交付：最终权重、最佳验证权重的指针、可恢复状态、tokenizer/config、数据与计算账本、阶段 lineage、固定评估和生成样本、实际支持的模态/长度，以及可复现推理入口。完成 base 预训练不等于完成指令对齐；SFT/RL 属于下一轮工作。

## 6. 实验边界与记录

### 6.1 只保留与生产直接相关的验证

- **不再新增常规科学探索 GPU 作业。**
- 首次生产准入：每个模型最多一项、共四项真实数据验收。使用最终冻结的首阶段 batch、数据与 LR 配方，50 次性能预热 +200 次测量；原 16K 档的 5M CE 规划上限不能直接约束 32K/64K 档。预算按完整更新窗口另行核算并写入记录，未冻结前不派发；不缩小 batch 冒充目标配置验收。实耗记录 input、CE 和 GPU 小时，性能预热不等于 LR warmup。
- MF1 的现有 acceptance 上限 2M 保持不变。50+200 在 16K global input 下可能超过该上限，应使用与生产共享 batch/loss/optimizer 实现的独立真实数据性能入口，明确记录全部优化器更新和 CE，不导出可冒充主训练的模型；该入口需要补齐时作为工程工作，不拆成多个 2M 作业规避上限，也不凭测量完成直接写 qualified。
- 正确性检查优先复用现有 CPU/小张量测试，不为每个接口再开训练实验。
- 发生具体失败后，每个受影响模型允许一次针对性修复复验；再次失败就记录工程阻塞及修改范围，不自动变成一轮参数搜索。
- MF1 执行优化以 **48 小时工程时间盒**为第一检查点，GPU 验证总时长建议上限 16 卡时。交付 profiling、修复、数值对齐和一次真实混合数据测量；达不到目标时明确剩余工作，不再续开 2M→20M→200M 的慢速诊断链。
- 后续长度/注意力阶段转换保留必要验证，但只验证即将使用的设置，不展开候选矩阵。它们属于生产阶段的准入任务。
- 不将现有 acceptance/diagnostic 运行事后改名计入正式 CE；预算、数据和 run_kind 的事实保持不变。

## 7. 算力与存储

### 7.1 算力与排期

默认一张 3090 承担一个独立模型任务，先使用 175 已准备环境的可用独占卡；MF1 达到生产准入后加入。每次派发重新核查进程归属、显存、环境、项目路径与存储，不凭低利用率认定空闲，不占用其他项目进程。239 作为确认环境/路径/配额后的可选执行位置，不使用历史设备快照分配资源。

执行顺序以第 1 节依赖为准。耗时采用各阶段真实混合数据的端到端速度估算：sum(阶段 token / 阶段吞吐) + indexer + 评估 + 存盘。短序列或合成测速不能外推全程，也不使用旧速度承诺完成日期。

MF1 近期真实首阶段图文吞吐目标约 1,000 CE/s，是项目排期目标，不是已达到的成绩或官方阈值。按第 6 节 48 小时工程时间盒与 16 卡时验证预算检查；已有优化先复用验收证据，未通过只处理明确剩余问题，不阻塞其他模型。

### 7.2 数据、缓存与权重预算

175 的新增产物规划上限为 **105GiB**。实际可写额度受磁盘保留线与其他已预约写入限制：

| 类别 | 上限 GiB | 控制方式 |
|---|---:|---|
| 规范化压缩文本、来源/去重索引 | 15 | 一份 canonical；有界 shard，按需从固定源补充 |
| token/必要元数据缓存 | 15 | 共享兼容 tokenizer 缓存；热 shard 轮换，不保存所有逐 token 位置数组 |
| 图像/视频热缓存 | 25 | 内容哈希去重、按 shard 预取/驱逐；验证媒体固定保留 |
| 主训练与选定里程碑权重 | 38 | 当前/上一恢复点 + 关键阶段推理权重；旧阶段不保留全部优化器副本 |
| 临时下载、解码和原子写入 | 10 | 写入预约与同盘 checkpoint 写入协调；结束后释放 |
| 日志、评估与其他元数据 | 2 | 指标全留，profiler 有界，样本限量 |
| **总计** | **105** | 不突破总额，不为四模型复制四套 raw/media |

开始数据构造或训练前重新读取可用空间，不把历史清理候选的预计释放量算作已释放。下列阈值按同盘所有本项目任务协调执行。

- **80GiB**：新 shard/新运行的可用空间保留线，同时扣除所有已预约写入；不足则 waiting_disk，不启动。
- **60GiB**：正在运行的本项目任务暂停新增消费，协调完成已预约的可恢复保存并退出；禁止各进程同时临时各写一个大文件。
- **50GiB**：继承现有底线，绝不以删除未知文件或绕过检查继续训练。
- 原子保存峰值按临时副本计算，不只看最终文件大小；存盘成功、加载检查通过之后才释放旧恢复点。
- 每日记录 du/df、最大目录、增长量、预约与实际差异。达到类别上限时回收该任务声明可驱逐的 cache；不能动其他项目文件。
- 需要扩展存储时先确认 239 的项目目录/配额和恢复方式，再同步一个哈希固定的 shard；目标挂载的空间与配额须重新核查。

5B 候选池是逻辑语料规模，不要求规范化文本、两套 tokenizer 编码、全部图片和解码帧同时常驻本地。缓存可驱逐的前提是内容可按固定 revision/hash 重建；无法重建的唯一原始文件必须保留或先做经过验证的归档。

### 7.3 历史产物与恢复点

历史检查点候选位于[存储候选清单](experiments/2026-09-10-pretraining-cutover/checkpoint-retirement-candidates.csv)。2026-09-10 已完成 20 项逐值/实际加载/哈希与活跃引用核查，回收 51.58GiB 优化器恢复文件，保留模型、tokenizer、最佳权重及报告；原清单作为候选快照保留，实际处置见[回收凭据](experiments/2026-09-10-pretraining-cutover/checkpoint-retirement.json)。另一个未通过筛查的候选保留。

处理前逐项确认：实验结束、无活跃运行或保留谱系依赖、保留 model 可加载且 config/tokenizer/评估证据齐全，并明确是否放弃该旧运行的精确恢复。保留活跃检查点、仍需复查的父链及原始日志/配置；不扫描所有权重一键删除。

正式主线保留当前/上一可恢复点和必要阶段推理权重，先验证新保存可加载，再轮换旧恢复点。临时原子写入的副本纳入峰值预约。内容可按固定 revision/hash 重建的缓存才可驱逐；不可重建的唯一原始数据先做验证归档。
