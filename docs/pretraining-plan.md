## 2. 数据

### 2.1 当前库存与后续供给

首阶段共享文本有 396,842 篇训练文档。合并代码、数学、中文和英文增量后，新库存为 **484,918 篇训练文档**：三个来源模型约 **676.9M CE**，MF1 约 **723.3M CE**，两套编码均已完成机械检查。这是同一语料的不同编码，不能相加；完整 10.5B 训练的后续供给仍按阶段准备。

文本由中文教育、英文教育、代码、数学/科学和对话来源组成。当前来源及处理方式见[数据说明](guides/data-sources.md)；固定 revision、文件校验值、分组与许可状态以各数据 manifest 和来源报告为准。

后续按各阶段的实际分域缺口补充，分别记录候选规模、独立语料量和训练累计 CE。每个模型按自己的 tokenizer 和 loss mask 计预算；已满足阶段需求的来源不继续为凑候选总量扩充。已使用的 shard 保持内容不变，新数据作为新组件绑定到后续阶段。

视觉来源包括逐子集记录许可的自然图像、OCR/文档、图表和 VQA，以及项目生成样本。视频记录原始视频身份、时间戳和采帧规则。MF1 全程目标保留 **1.5M 独立图片、5M 图片曝光和 120K 视频曝光**；这些是供给计划，尚未全部完成。图像特征 token、媒体曝光和视觉文本 CE 使用不同计数。

真实视频使用固定版本的 [Meta PE-Video 训练集](https://huggingface.co/datasets/facebook/PE-Video/tree/43a297dde47e2036721f259397df04b3c338d002)（CC-BY-NC-4.0），按字节范围取源文件并保留真实帧、时间戳和独立视频分组。首批与 MF1 增量已完成，MF1 合计 42,846 个独立训练组。P1 使用新增供给后，视频 8M CE 的预计轮次由仅用首批时的 12.12 遍降至 2.88 遍。

双页来源为固定版本的 [Docmatix](https://huggingface.co/datasets/HuggingFaceM4/Docmatix/tree/0725b65616e0e5f6024be10e38ddf8d8c48664fd)，只取同一文档的完整两页与完整问答，记录为 `multiimage_multipage`。它提供多页文档问答，不代表网页段落与图片交错训练；网页交错数据后续单独安排，不因此延后已具备有效多模态供给的 K2/Q2。

### 2.2 处理与留出

数据流水线执行以下处理，并保留可重现的输入版本与结果：

1. 固定来源、文件、采样 seed、样本/媒体身份及校验值，按选定分片读取。
2. 规范化编码、网页模板和段落；检查语言、长度、乱码、代码与媒体可解码性。
3. 按文档、代码仓库、原图、视频和同图问答分组，进行精确及近重复去重，再划分训练/验证/测试。
4. 过滤与固定评测集重合的样本及其相连组。合并库存时保留既有留出组，test 优先于 val。
5. 冻结 tokenizer，检查 round-trip、控制 token、文档边界、loss mask、媒体位置和截断；编码后再次核对计数与文件完整性。

划分目标为 train 98.5%、val 0.5%、test 1%；报告同时保留实际独立组数和比例。后续阶段继承既有划分；若哈希抽样的实际比例低于目标，在该阶段的执行计划中记录真实下界和原因，不将已用于训练的记录移入验证集。固定验证 token 量与独立媒体组数仍单独检查。

本轮未进行完整人工内容审核，已记录维护者豁免；自动清洗、去重、污染和编码检查继续执行，见[审核范围](experiments/2026-09-10-pretraining-cutover/human-review-waiver.json)。

文本污染检查固定 HumanEval、MBPP、GSM8K 的版本和文件 hash；视觉固定 ChartQA 与 TextVQA 的留出图像身份。规范化文本片段、媒体文件/RGB hash 和 pHash 用于查找候选，命中后按相连组处理。该检查有明确覆盖范围，不能排除所有改写、翻译或图像变换。评测原文和答案不随代码分发。

### 2.3 混合比例

下表按**文本子集的 CE**计算，视觉另计。MF1 的领域名称由自身采样器定义，使用时保留对应映射。

| 模型 | 中文 | 英文 | 代码 | 数学/科学 | 对话/结构化 |
|---|---:|---:|---:|---:|---:|
| Kimi | 45% | 25% | 15% | 10% | 5% |
| Qwen | 40% | 25% | 20% | 10% | 5% |
| DeepSeek | 40% | 25% | 20% | 10% | 5% |
| MF1 | 42% | 28% | 12% | 10% | 8% |

K2 已绑定的混合与 Q2 接续计划按 **1.2M 次图像出现**分配如下；视频另有 20K 样本预算，不混入这张表或文本 CE 比例。

| 分母 | caption | OCR/文档 | 图表 | VQA | 完整双页 QA |
|---|---:|---:|---:|---:|---:|
| 图像出现次数 | 20% | 56% | 6% | 16% | 2% |
| QA 采样权重 | 20/99 | 56/99 | 6/99 | 16/99 | 1/99 |

双页 QA 每条含两张图，因此 2% 图像出现对应 12K 条双页 QA，不能直接填成 2% 的 QA 采样权重。当前池加新自然候选约有 415.7K 个训练 RGB 身份；图表的 105.4K 条 QA 仅对应约 19.3K 张图，是降低图表比例的直接原因。候选下自然图本阶段平均约 5.17 次曝光，计入先前阶段后更高；同图不同问题不算新图。

该比例是现有供给下的项目选择，并非官方配方或已验证最优值。[Kimi 报告 §3.1](https://arxiv.org/html/2607.24653v1#S3.SS1)给出视觉数据类别与处理原则，没有规定这些比例。所需的每域 QA 轮次在 4 遍内；这不等于每张图最多出现 4 次，也不把 SFT 的两遍约束套到预训练。双页训练库存对应约 3.40 遍 QA 曝光。旧自然图/OCR 补充池按需要复用，不作为必须全部处理的新门槛。

阶段供给报告同时列出各域独立文档/媒体量、可用 CE、预计消费、曝光倍率和缺口。有限算术模板、重复图片或诊断色块不能用于填平正式数据缺口。预训练对话混合与后续 assistant-only SFT 的监督范围分别定义。

### 2.4 编码与缓存

文本采用紧凑 token 流和文档边界；媒体保存必要位置、mask 与来源元数据。uint16 仅用于所有 token ID 都不超过 65535 的词表。按需构造训练窗口，恢复时还原游标、采样 RNG 和混合计数。

部分原始图片与生成 OCR 像素保留在本地，其余媒体由存储主机通过内网直连按需提供。远程读取使用内容哈希校验与有界缓存，验证媒体固定保留；原始文件与热缓存分别统计。视觉编码器参与训练，其输出不作为固定 embedding 缓存。

数据来源、许可和未解决的归属问题见[数据说明](guides/data-sources.md)。原始语料与训练权重不随源码包分发。

## 3. 模型与配方

### 3.1 阶段预算

M 表示百万，B 表示十亿。主 CE 是参与主语言损失的预测位置；索引器使用有效 input token 单独计量。

| 模型 | 阶段顺序与主 CE | 主 CE 总量 | 索引器预算 |
|---|---|---:|---:|
| MiniKimi-K3 | K1 0.2B → K2 1.2B → K3 0.4B → K4 0.2B | 2B | 无独立阶段 |
| MiniQwen4 | Q1 0.3B → Q2 1.2B → Q3 indexer → Q4 1B → Q5 0.5B | 3B | 首版 20M input；原方案范围 20–60M |
| MiniDeepSeek-V4 | D1 0.25B → D2 0.5B → D3 indexer → D4 1.5B → D5 0.25B | 2.5B | 首版 10M input；原方案范围 10–30M |
| MiniFrontier1.0 | P0 0.2B → P1 0.8B → indexer → P2 1.4B → P3 0.6B | 3B | 40M input |
| MiniDeepSeek-V4.1 | D1 0.25B → D2 0.5B → D3 1.5B → D4 0.25B；全程直接稀疏 | 2.5B | 无独立阶段，联合训练索引器 |
| MiniFrontier1.1 | P0 0.2B → P1 0.8B → indexer → P2 1.4B → P3 0.6B | 3B | 40M input |

六版本合计 **16B 主 CE**，各自独立计量；这不是去重语料规模。两版 DeepSeek 本轮均训练文本，后续视觉训练与评估单列，不计入文本完成度。V4.1 与 MF1.1 的架构及版本边界分别见[模型页](models/minideepseekv41.md)和 [MF1.1 说明](models/minifrontier11.md)。

### 3.2 首阶段执行配置

batch 是每次优化更新的非 padding input token 目标；microbatch 是一次前后向的样本数上限。样本长度不同，实际累积次数也不同。以下保留原四模型首阶段的启动配置；新增版本的参数、优化器和日程见[联合方案](training-strategies/2026-09-14/07-v41-mf11-implementation-and-training.md#预训练安排)。

| 模型 | 浮点参数量 | 全局 input 目标 | microbatch | 优化器与峰值 LR |
|---|---:|---:|---:|---|
| Kimi | 204,526,216 | 32,768 | 64 | kimi_muon：Muon 0.005，Adam 3e-4；视觉 1e-4，投影 3e-4 |
| Qwen | 513,405,536 | 16,384 | 32 | qwen_muon：Muon 0.01，Adam 3e-4；视觉 1e-4，投影 3e-4 |
| DeepSeek | 243,983,472 | 32,768 | 16 | deepseek_muon：Muon/Adam 共用 3e-4 |
| MF1 | 228,235,809 | 16,384 | 8 | AdamW：主干 3e-4，视觉与标量 1e-4 |

三个来源模型使用 64K tokenizer，首阶段上下文上限 1024。MF1 使用 32K tokenizer，P0 以 512/1024 长度混合训练。四模型 seed 均为 42。完整参数组、MTP 系数和依据见[工作配方](experiments/2026-09-10-pretraining-cutover/working-recipes.md)与 [configs/experiments.json](../configs/experiments.json)。

后续阶段的实际 microbatch：K2 为 16、D2 为 8，二者上下文上限 2048；MF1 P1 为 8，按 70%/30% 混合 1024/2048。Q2 启动值取 8、上限 2048，以预留更长序列和媒体的激活显存；Q2 实测吞吐由运行记录持续更新。各模型全局 input 目标和连续学习率日程保持表中定义。

各优化器的归一化定义不同，原始 LR 不直接横比。DeepSeek 的 `--lr` 控制两分支，`--muon-lr` 不生效；其余分组和衰减参数见工作配方。

### 3.3 学习率与模态课程

| 模型 | 学习率日程 | 长度与模态安排 |
|---|---|---|
| Kimi | 整条 2B 主 CE：前 20M warmup，随后 cosine 到 0.1 倍 peak | K2 1024/2048；K3 2048/4096；K4 混合长度与高质量数据。图像曝光 K1/K2/K3/K4 为 0.2M/1.2M/0.5M/0.1M，K2/K3 视频为 20K/10K |
| Qwen | Q1/Q2 前 15M warmup 后保持；Q4 主干取 0.4 倍 peak、5M warmup；Q5 500M 冷却 | Q1/Q2 dense，Q3 仅训练 indexer，Q4/Q5 sparse。图像曝光依次 0.3M/1.2M/0.8M/0.2M；视频 Q2/Q4/Q5 为 20K/20K/10K |
| DeepSeek | 前 25M warmup，保持到累计 2B，最后 500M cosine | D1/D2 文本 dense；D3 indexer；D4/D5 sparse。D5 MTP 系数由 0.3 降至 0.1 |
| MF1 | 前 2M warmup，保持到累计 2.4B，最后 600M cosine 到 0.1 倍 peak | P0 512/1024，P1 1024/2048，P2 2048/4096，P3 2048/4096/8192 |

索引器各自使用独立日程。MF1 的 P0/P1/P2 视觉 CE 占 20%，P3 占 25%；全程为 **630M 视觉 CE + 2.37B 文本 CE**。Kimi/Qwen/MF1 的视觉编码器与语言主干从首阶段联合学习。

MF1 P1 已采用旧 49 特征与新 100 特征图像的混合课程，分别记录分辨率、视觉 CE 和曝光量。P0 的既有输入保持不变。P1 视觉 CE 的实际比例为 caption 33%、OCR/文档 35%、VQA 22%、图表 5%、视频 5%：图表池虽有 105,417 条 QA，独立图像仅 19,289 张，原 10% 比例预计每图曝光约 16.16 次，调整后约 8.08 次。该选择用于减少同图重复，效果由正式训练的固定分域验证判断。

长上下文阶段需要真实长文与位置覆盖。MF1 的 8K 和各模型的视频阶段只有完成对应训练与评估后才能列为已训练能力。

<a id="initialization"></a>

## 4. 恢复与阶段转换

| 场景 | 权重 | 优化器与数据状态 |
|---|---|---|
| 首阶段开始 | 随机初始化，包括视觉模块 | seed、优化器、采样器、RNG、计数从零建立 |
| 同阶段恢复 | 本运行完整检查点 | 恢复 optimizer、router、采样游标、RNG 和 token 账本，严格核对配方与数据 |
| 跨阶段转换 | 前一正式阶段检查点 | 按参数名继承适用状态；明确记录冻结、暂存、重建和阶段计数 |
| 执行优化后恢复 | 保留的完整检查点 | 仅允许经验证的执行变更，并记录新旧源码、证据与检查点校验值 |

三个来源模型的普通 `--init` 会新建优化器与运行计数；连续阶段转换使用 `--pretraining-program / --pretraining-phase / --schedule program`。MF1 使用 P0→P1→indexer→P2→P3 的连续路径。主 CE 跨阶段累计，索引器 input 另计；主干 moments 在索引器阶段暂存。

后续阶段可以稍后补充数据绑定，已经训练阶段的配置与绑定继续严格校验。采样数据、长度或混合改变时记录采样器重建；其余条件匹配时继承。旧 pilot、SFT、诊断或测速权重不用于本轮正式首阶段初始化。

CPU 预取、媒体缓存和优化器批量执行的恢复依据见[执行优化记录](audits/training-infrastructure.md)。开发目录与活跃训练的冻结源码分开维护。

<a id="acceptance"></a>

## 5. 验证与停止条件

首阶段复用已有正确性与数据检查，直接在正式更新中观察损失、显存和吞吐。2026-09-11 的[启动调整](experiments/2026-09-10-pretraining-cutover/direct-training-start.json)取消了 Kimi、Qwen、MF1 额外的独立 pilot 和性能验收。新数据适配执行相关的最小 CPU 检查，通过后构造数据；独立 GPU smoke 不作为每个阶段的默认前置。出现具体问题时再做必要的短复现和修复，不为估算性能消耗大额训练 token。

### 5.1 日常观察

- 首 100M 每 10M CE 固定验证一次，之后每 50M 一次；周期验证约 1M CE，阶段末约 5M CE。实际耗时和 CE 分母均记录。
- 同一模型以固定留出集的总体、分域 NLL 判断变化。不同 tokenizer 的 token NLL 不直接排名；跨模型比较使用相同原文的 byte 归一化损失及能力任务。
- 在 100–200M 观察基础续写、复制、算术/代码与适用的视觉样本。记录重复、偏题和终止行为；基础续写与聊天指令遵循分别评价。
- 正式视觉评价至少 1,000 个独立媒体组，包含正常、错配、置黑及必要的时序置换。日常置黑 NLL 只作为诊断，不能替代完整视觉能力评估。

loss mask、CE 归一化、因果边界、媒体标签、数据损坏、NaN/Inf 或恢复错误需立即处理。显存/磁盘不足时保留可恢复点后停止对应任务。warmup 后固定验证连续三次相对恶化约 5% 以上，排除统计与混合变化后暂停诊断；持续严重生成退化也需结合固定验证复查。

### 5.2 阶段边界

| 转换 | 要求 |
|---|---|
| Qwen dense→sparse | 绑定同一权重与数据，检查 indexer 有效 query 和梯度范围；本地目标为语言 NLL 相对退化≤2%、固定视觉指标下降≤3 个百分点 |
| MF1 P1→indexer→P2 | text/code/OCR/video 各域有效注意力质量捕获≥90%，相对 NLL 增量≤1%，视觉准确率下降≤2 个百分点；报告绑定实际父检查点 |
| 长上下文、多图、视频 | 对即将启用的长度、媒体布局、显存和恢复做针对性检查，记录独立数据覆盖 |

转换检查只影响对应后续阶段。多轮对话、thinking 协议、奖励和草稿路径在进入相应训练前验证。

## 6. 实验记录

本轮算力用于基础预训练。新的 batch/LR 网格、架构消融和补种子实验另行安排；性能优化先定位瓶颈，再做短数值对照和实际运行观察。

运行登记继续使用 `configs/experiments.json`、`scripts/experiment_registry.py` 与本地 `outputs/experiment-registry`。每条记录包含：

- 用途、模型/阶段、父检查点、源码版本、config/tokenizer/data hash；
- seed、参数组、精度、优化器、LR/日程、batch 与累积规则；
- CE、input、索引器、媒体曝光和独立媒体量；
- 实际 GPU 时间、吞吐、显存、磁盘、检查点保留规则；
- 固定验证、生成结果、结束原因、限制和后续决定。

正式训练独立使用 TensorBoard，默认端口 6008，按 `<model>/<phase>` 展示 `train / eval / perf`。展示同步从原始 JSONL 和 event 生成独立视图，保留 step 与时间戳；启动、缓存回收、QK 裁剪等事件保留在原日志。旧诊断和测速留在原实验入口。

公开档案只保留必要的配置、数值、曲线和结论；机器地址、容器标识、原始样本及权重保存在本地运行目录。历史日期记录不覆盖新的正式训练状态。

<a id="resources"></a>

## 7. 算力与存储

### 7.1 执行安排

一张 3090 同时运行一个模型任务。训练集中在主工作站，辅助工作站仅提供已有媒体的存储和文件服务。每次启动核对设备归属、可用显存与空间；健康任务保持原配置运行。

两机文件传输使用内网直连，禁用环境代理和 SSH 跳板；直连失败时停止传输并报告。主机地址与 GPU UUID 仅保存在本地记录。

ETA 使用本阶段实际混合数据的端到端耗时估算，另计验证、存盘和数据等待；短序列合成测速不用于承诺全程日期。

### 7.2 空间预算

以下为主工作站本轮新增产物的规划上限；共享缓存和编码按实际物理占用计算。

| 类别 | 上限 GiB |
|---|---:|
| 规范化文本、来源与去重索引 | 15 |
| token 与必要元数据缓存 | 15 |
| 图像/视频热缓存 | 25 |
| 主训练与保留里程碑权重 | 38 |
| 临时下载、解码、原子写入 | 10 |
| 日志、评估及其他元数据 | 2 |
| **合计** | **105** |

本轮阶段衔接允许文本与媒体编码临时合计 **24 GiB**，按 inode 去重计物理占用，写入前另留 64 MiB 余量。存在并行任务时，未写完组件也计入预留额度；旧阶段结束且依赖核对后，回落到 15 GiB 常态目标。

新分片和新运行按 **80 GiB** 可用空间预留线协调预约，原子保存包含临时副本峰值。低于 **60 GiB** 时协调暂停新增消费并保存退出，**50 GiB** 为绝对底线。处理前读取实际空间，不把预计清理量计为已释放。

保留当前恢复点、必要的上一恢复点和关键阶段推理权重；新保存确认可加载后再轮换。缓存仅在固定来源和 hash 可重建时驱逐；唯一原始文件先做验证归档。旧实验产物按依赖与保留用途逐项处理，见[产物保留规则](operations/artifact-retention.md)和[已有回收记录](experiments/2026-09-10-pretraining-cutover/checkpoint-retirement.json)。

## 8. 交付

每个基础模型完成相应预算与阶段后，提供权重、tokenizer/config、恢复状态、数据与计算账本、阶段继承记录、固定评估和生成样本，并说明实际训练过的模态及长度。基础预训练完成后再推进指令对齐；当前权重尚未达到可用对话模型的发布标准。

公开发布另需完整模型卡、权重校验值、推理步骤及各自产物许可。研究预览版可以先提供实现、可复现小流程与实验档案，明确尚未完成的训练。

日常进度记录各阶段 CE/目标、验证变化、实测速度、空间和数据缺口。设计依据见[方案索引](training-strategies/README.md)，结果见[实验档案](experiments.md)，实现检查见[审计记录](audits/README.md)。
