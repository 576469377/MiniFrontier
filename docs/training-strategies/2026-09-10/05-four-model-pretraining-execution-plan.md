### 3. 剩余实验的硬边界

- **不再新增常规科学探索 GPU 作业。**
- 首次生产准入：每个模型最多一项、共四项真实数据验收。使用最终冻结的首阶段 batch、数据与 LR 配方，50 次性能预热 +200 次测量；原 16K 档的 5M CE 规划上限不能直接约束 32K/64K 档。预算按完整更新窗口另行核算并写入记录，未冻结前不派发；不缩小 batch 冒充目标配置验收。实耗记录 input、CE 和 GPU 小时，性能预热不等于 LR warmup。
- MF1 的现有 acceptance 上限 2M 保持不变。50+200 在 16K global input 下可能超过该上限，应使用与生产共享 batch/loss/optimizer 实现的独立真实数据性能入口，明确记录全部优化器更新和 CE，不导出可冒充主训练的模型；该入口需要补齐时作为工程工作，不拆成多个 2M 作业规避上限，也不凭测量完成直接写 qualified。
- 正确性检查优先复用现有 CPU/小张量测试，不为每个接口再开训练实验。
- 发生具体失败后，每个受影响模型允许一次针对性修复复验；再次失败就记录工程阻塞及修改范围，不自动变成一轮参数搜索。
- MF1 执行优化以 **48 小时工程时间盒**为第一检查点，GPU 验证总时长建议上限 16 卡时。交付 profiling、修复、数值对齐和一次真实混合数据测量；达不到目标时明确剩余工作，不再续开 2M→20M→200M 的慢速诊断链。
- 后续长度/注意力阶段转换保留必要验证，但只验证即将使用的设置，不展开候选矩阵。它们属于生产阶段的准入任务。
- 不将现有 acceptance/diagnostic 运行事后改名计入正式 CE；预算、数据和 run_kind 的事实保持不变。

### B2. 数据流程及交付

1. **来源冻结**：dataset/revision/config/files、采样 seed、原文/媒体 ID、校验值和条件；流式读取选中分片，拒绝全库下载。
2. **规范化**：编码、HTML/模板噪声、语言、极端长度、乱码、重复段落、代码解析与媒体可解码检查。保留原文到规范化样本映射。
3. **去重和划分**：先按文档/仓库/原图/视频/同源多问答分组；精确和近重复去重后，以组分 train 98.5%、val 0.5%、test 1%。不能逐行随机把同图问答拆开。
4. **污染核查**：按已选验证与 benchmark 的原始样本/衍生身份过滤；保留匹配规则和剔除数量，test 封存，不用于反复挑配方。
5. **人工抽查一次**：每个主要来源/领域至少 100 条，图像/视频按任务分层；记录可读性、标签是否对应媒体、来源缺项和异常率。出现实质问题时定向修复，不反复重审已固定的来源。
6. **tokenizer 与编码**：只用训练划分，冻结词表/控制 token；检查中英文/代码切分、round-trip、越界 token、文档边界、loss mask、媒体 span 和截断。32K/64K 不直接横比 token NLL。
7. **manifest 准入**：每域独立文档/媒体量、可用 token、计划消费量、曝光与重复率、文件大小、哈希、验证集合、处理代码版本均明确后，才标 formal_admission=true。

交付文件以正式 data manifest 为索引，至少包含 source_allowlist、split manifest、质量报告、去重/污染报告、tokenizer 报告、按阶段混合表、数据账本和存储账本。不要仅将原配置的 not_prepared 改成 prepared。

| MF1 | 42% | 28% | 12% | 10% | 8% 结构化 |

首轮共享文本库存按参考 tokenizer 准备至少 **0.5B 个去重训练 token**，各模型的第一个生产阶段必须有足量、匹配领域比例的可用 token；这是交付切片，不是新增 0.5B 小实验。随后按 1.5B、约 5B 的候选池规模补齐后续阶段；已准入 shard 的内容不可原地替换。

视觉保留原计划规模：MF1 候选 **1.5M 独立图片、5M 图片曝光、120K 视频曝光**；实际视频独立数另报。前三者绝不可混称为“训练了几百万张不同图片”。Kimi/Qwen 共用底层媒体文件，但各自保留处理器、模态位置和采样账本。自然图片、OCR/文档、图表、多图必须都有独立留出；生成色块仅用于回归检查。

不要求一次将 1.5M 图片全部落在 175。本地使用有界媒体 shard 缓存，固定远端 revision 与哈希；持续预取下一分片。不可把可训练的随机视觉塔输出预先缓存成固定 embedding 来节省空间，那会改变原生视觉训练目标。

### B4. 需要补的工程工作

- 三个来源模型已有 memmap 数据路径，优先复用；无需再造一套通用加载器。
- MF1 的 RecordDataset 当前按记录打开 JSONL、验证并编码；已有编码器输出二进制 shard，但训练消费接入、批量合并和多模态边界必须补齐。
- 当前 MF1 编码器仅 ids/labels/三轴 positions 就至少 **18 bytes/input token**，还没算 JSON 索引中的逐 token 数组。对 5B 全量编码底线约 83.8GiB，不能只按 uint16 的 2 bytes/token 估存储。
- 采用按需 shard：纯文本只保留紧凑 token 流、文档边界和必要 mask，position 可按确定规则恢复；媒体只保存必要的稀疏元数据。压缩前后对同一批样本验证 token、labels、位置和模型输出。
- uint16 需确认最大 token ID≤65535，包含所有新增控制 token；否则采用 uint32。不能静默截断。
- 每条主线保存 shard/cursor、shuffle/采样 RNG、混合累计账本、媒体重复与数据版本，恢复后不重新从首个 shard 开始。

## 四、阶段 C：完成四模型的正式预训练

### C1. 本轮完成范围与预算

预算沿用现有模型专项计划，不将 20M pilot 当作预训练完成。四模型主训练共 **10.5B CE**；indexer 的 input token 另计。

| 模型 | 生产阶段顺序 | 主 CE 总量 | indexer 另计 |
|---|---|---:|---:|
| Kimi | K1 0.2B → K2 1.2B → K3 0.4B → K4 0.2B | **2B** | 无独立稀疏 indexer 阶段 |
| Qwen | Q1 0.3B → Q2 1.2B → Q3 indexer → Q4 1B → Q5 0.5B | **3B** | Q3 20–60M input；首版按 20M 排期，是否增量按预置 indexer 指标判断 |
| DeepSeek | D1 0.25B → D2 0.5B → D3 indexer → D4 1.5B → D5 0.25B | **2.5B 文本** | D3 10–30M input；首版按 10M 排期 |
| MF1 | P0 0.2B → P1 0.8B → indexer → P2 1.4B → P3 0.6B | **3B** | 40M input |

这里的 DeepSeek 交付为现有文本主配置；项目 Vision-Exp 是后续扩展，不能说它在本轮文本预训练中已经学过图像。其 V1 10–30M CE warmup、V2 240M、V3 60M 保留在专项策略；在四个 base 主目标后再推进，另列预算和参数量。

### C2. 模型分别推进

**Kimi**
- K1 长度 512→1024，约 200K 图像曝光；K2 1024→2048，约 1.2M 图像/20K 视频；K3 2048→4096，约 500K 图像/10K 视频；K4 混合长度、较高质量数据，约 100K 图像。
- 原生 MoonViT 随阶段训练，保持文本与视觉参数组的 LR、梯度与曝光记录。
- 路由/AttnRes/KDA 指标作为健康监测；不为达到漂亮的专家均匀曲线反复换配方。
- 进入更长阶段要求真实长文和位置覆盖，拼接短样本的总长度不能当长上下文学习。

**Qwen**
- Q1/Q2 使用 dense_pretrain；Q3 冻结合格 dense teacher，仅训练声明的 indexer；Q4/Q5 才使用 sparse_cpt。
- 媒体曝光按旧计划依次约 300K、1.2M、800K、200K，视频在 Q2/Q4/Q5 分别约 20K/20K/10K；图像数是曝光，独立数必须另报。
- Q3 的前置条件在 Q2 结束时处理，无需在 Q1 前训练完整 indexer。保存 teacher 对应权重、索引目标、有效 query 数及梯度范围。
- dense→sparse 以同一权重、同一数据比较；建议本地验收阈值为语言域 NLL 相对退化≤2%、固定视觉指标下降≤3 个百分点，达不到时只修复/延长该转换，不重跑 Q1/Q2。

**DeepSeek**
- D1/D2 先建立文本基础，D3 进行 indexer 训练，D4/D5 做稀疏继续预训练及收尾。
- compression ratio、Hash/MoE、mHC 和 MTP 按冻结结构保留；监控梯度、路由与有效压缩窗口。
- 没有视觉的阶段不凭空计算媒体预算；未来接 Vision-Exp 先验证原文本模型输出保持，再做视觉 warmup 与联合训练。
- 固定 batch 与预先声明的 batch ramp 保留为原计划候选，在正式 D1 前定案。选定 ramp 后从第 0 步写入完整 schedule，后续按 CE 节点变更，不在各节点随机重启；不把 pilot 的增长节点直接冒称正式或官方参数。

**MF1**
- 保留既定 228M 结构，先修复执行与数据路径，不在该时间盒内新增组件。
- P0/P1/P2 的视觉 CE 占 20%，P3 占 25%；3B 中共 **630M 视觉 CE、2.37B 文本 CE**。视觉 feature token、媒体曝光和视觉文本 CE 分开计数。
- 原生随机视觉从 P0 就参与；不能把纯文本预训练完成当作 MF1 整体预训练完成。
- P0 长度 512/1024，P1 1024/2048，P2 2048/4096，P3 2048/4096/8192；P3 的 8K 需要真实训练和评估通过，OOM 或未实现时明确阶段未完成，不能降成 2K 后继续宣称 8K 完成。
- indexer 插在 P1 与 P2 之间；P2 保留当前代码的严格门槛：text/code/OCR/video 各域有效注意力质量捕获至少 90%，相对 NLL 增量≤1%，视觉准确率下降≤2 个百分点，且评估文件必须绑定实际父检查点；不采用 Qwen 表里的宽松示例覆盖 MF1 门槛。标准单轮和媒体协议可验证后先训练，thinking/RL 不作为前置条件。
- 当前性能不足是工程阻塞，不是再做一轮慢速语言小实验的理由。

### C3. 首阶段准入与连续训练

四个模型各自通过以下项目就开自己的主线，不等待其他模型全部就绪：

1. 模型、tokenizer、loss/媒体和因果边界正确性；
2. 首阶段正式数据已准入，且持续预取能供给；
3. 一次最终真实配置验收：有限损失/梯度、真实 CE 归一化、恢复、首阶段最大长度/媒体内存边界；
4. 保留物理显存至少 2GiB，当前任务独占一张卡，磁盘预算预约成功；
5. 完整记录、当前版本有效准入证据和首阶段输出目录。

正式 K1/Q1/D1/P0 必须在新目录随机初始化，init=null、resume=null；不导入任何旧 pilot/诊断/batch/SFT 权重，也不导入生产性能验收的权重，模型及随机视觉塔、optimizer、采样器/RNG、训练账本从零建立。先完成完整预算与配方冻结，再开始正式第 0 步。

只有同一冻结正式运行内部的 20M/50M/100M 存盘点才可按原配方 exact resume；不能先跑完一个预算 20M 的旧实验，再改 batch/LR/总预算并称精确续训。当前训练器也绑定 microbatch，禁止删除校验字段绕过。

阶段转换绑定前一正式阶段 checkpoint/hash，并逐项记录 model/optimizer/router/main CE/phase CE/sampler/RNG 的继承或重建。MF1 沿用已有连续阶段分支；三来源模型按专项策略补齐状态转换或明确记录阶段重启。后续阶段继承本轮已学权重，不重新随机初始化；这一点与“正式首阶段禁止继承旧实验”同时成立。

### C4. 验证与停止规则

- 训练日志按固定窗口统计 NLL、梯度、每域 CE、媒体曝光、吞吐与显存；损失比较使用相同领域/相同验证集。
- 首 100M 每 10M CE 做一次中等规模固定验证；之后每 50M；阶段末完整验证。定期验证约 1M CE，阶段末约 5M CE。实际评估耗时控制在训练总时间约 5% 内，变更频率必须记录。
- 图片/视频按独立原始媒体分组留出；正式视觉评价至少 1,000 个独立组，包含正常、错配、置黑与必要的时序置换。色块指标仅占回归小部分。
- 固定生成集分成自然文本续写、阅读/复制、算术/代码、视觉；对基础预训练模型不以“会遵循聊天模板”作为唯一放行条件。SFT 诊断权重与 base 权重分开。
- 同一 tokenizer 内看域 NLL；跨 tokenizer 采用固定原文的 byte 归一化损失及实际能力任务。不同模型不能凭 token NLL 高低宣布架构优劣。
- NaN/Inf、标签/边界错误、数据损坏、磁盘/显存越界立即停止对应任务，保留最近可恢复点。
- warmup 后，若同一固定验证集连续三次显著恶化（建议相对上升≥5%，并排除数据混合和统计波动），暂停该运行，检查数据/优化器/实现；不临时换目标或自动开参数网格。
- indexer 和长上下文转换的失败只阻挡下一阶段。没有完成预算及阶段验收就标 incomplete/blocked，不用“训练完了”替代。

最终每个模型交付：最终权重、最佳验证权重的指针、可恢复状态、tokenizer/config、数据与计算账本、阶段 lineage、固定评估和生成样本、实际支持的模态/长度，以及可复现推理入口。完成 base 预训练不等于完成指令对齐；SFT/RL 属于下一轮工作。

## 五、算力顺序与时间预算

默认每模型一张 3090、每张卡一个训练任务。优先使用 175 已有环境的可用独占卡：Kimi、DeepSeek、Qwen 各一张，MF1 优化/就绪后再占一张。GPU 6/7 的其他进程不在本计划处理范围。239 可用于已经确认路径和输入的迁移/独立主线；本轮只确认了设备瞬时状态，不因某块大盘有空间就假定它是项目配额。

建议执行时间表是工作目标，实际依赖数据下载和修复耗时：

| 时段 | 必须交付 |
|---|---|
| T0–半天 | 实验结论/处置、冻结工作配方、存储清单、主线依赖表 |
| T0–第 2 天 | 首批数据清洗/分组/去重、tokenizer、编码；三个来源模型的生产准入；MF1 执行优化首轮 |
| 第 3–5 天 | 首阶段数据持续供给，已就绪模型进入正式主训练；不得为了继续补探索而推迟 |
| 之后 | 同一主线按 K/Q/D/P 阶段推进，阶段末验证和明确交付；不重启研究网格 |

不能根据短序列最优速度承诺全流程完成日期。供预算判断的 512 长度示例：

| 模型 | 已观测速度口径 | 若假定全程维持该速度，主 CE 用时 |
|---|---|---:|
| Kimi | 固定 16K、上限 64，完整 1M 短作业约 4,114 CE/s | 2B 约 5.6 卡天 |
| Qwen | 固定 16K、上限 64，约 1,494 CE/s | 3B 约 23.2 卡天 |
| DeepSeek | 固定 16K、上限 32，约 3,157 CE/s | 2.5B 约 9.2 卡天 |
| MF1 | 合成稳态 66.32 CE/s，不含正式图文完整成本 | 3B 约 524 卡天 |

前三项也未覆盖所有长序列和正式媒体比例；MF1 口径又不同，表格用于看数量级，不用于模型间效率排名或承诺排期。

MF1 的近期工程目标设为真实首阶段图文至少约 **1,000 CE/s**；这是本项目可承受时长的目标，不是已达到的性能或来自技术报告的阈值。达到后仍需分阶段实测，按 sum(阶段 token / 阶段端到端吞吐) 加 indexer、评估、保存时间排期。若目标未达，输出明确的剩余工程方案；其他三个模型不因此暂停。

## 六、存储控制：先解决约 192GiB 的实验产物累积

### 1. 当前账目与立即处理的候选

当前可用 136.63GiB；计划生成了 **20 个历史恢复检查点候选，共 51.58GiB** 的清单。这些目录已存在独立 model.pt；候选包含旧 recipe/LR/MTP、已完成 batch16 和短性能试验。

这是候选清单，**没有执行删除，也未把可释放量当作已经释放**。实际处理前逐文件核对：
- 对应实验结束，且不被活跃进程/已保留续训依赖引用；
- model.pt 可加载、对应配置/tokenizer 可重建，保存校验值；
- 明确放弃该历史运行的精确 resume，仅保留复评/初始化能力；
- 当前 Qwen 活跃检查点、MF1 需要保留的初始化链、原始日志/配置/证据不在此候选删除范围。

不扫描全局 *.pt 后一键删除。补充清理只对已明确结束的临时测速权重、重复导出、可重建缓存逐项列出；冻结源码很小，不是主要空间来源。

### 2. 每台生产主机的新增预算

在完成核对后的候选回收并重新测量空间后，175 新增产物上限先设 **105GiB**：

| 类别 | 上限 GiB | 控制方式 |
|---|---:|---|
| 规范化压缩文本、来源/去重索引 | 15 | 一份 canonical；有界 shard，按需从固定源补充 |
| token/必要元数据缓存 | 15 | 共享兼容 tokenizer 缓存；热 shard 轮换，不保存所有逐 token 位置数组 |
| 图像/视频热缓存 | 25 | 内容哈希去重、按 shard 预取/驱逐；验证媒体固定保留 |
| 主训练与选定里程碑权重 | 38 | 当前/上一恢复点 + 关键阶段推理权重；旧阶段不保留全部优化器副本 |
| 临时下载、解码和原子写入 | 10 | 写入预约与同盘 checkpoint 写入协调；结束后释放 |
| 日志、评估与其他元数据 | 2 | 指标全留，profiler 有界，样本限量 |
| **总计** | **105** | 不突破总额，不为四模型复制四套 raw/media |

若 51.58GiB 候选全部通过并回收，136.63+51.58-105≈83.21GiB，刚能满足较保守的 80GiB 运行保留线。实际不能依赖这条静态算式：其他用户写盘、候选未获准处理或编码放大都会改变结果。

- **80GiB**：新 shard/新运行的可用空间保留线，同时扣除所有已预约写入；不足则 waiting_disk，不启动。
- **60GiB**：正在运行的本项目任务暂停新增消费，协调完成已预约的可恢复保存并退出；禁止各进程同时临时各写一个大文件。
- **50GiB**：继承现有底线，绝不以删除未知文件或绕过检查继续训练。
- 原子保存峰值按临时副本计算，不只看最终文件大小；存盘成功、加载检查通过之后才释放旧恢复点。
- 每日记录 du/df、最大目录、增长量、预约与实际差异。达到类别上限时回收该任务声明可驱逐的 cache；不能动其他项目文件。
- 需要扩展存储时先确认 239 的项目目录/配额和恢复方式，再同步一个哈希固定的 shard；不能在 /data 已满的挂载上默认创建副本。

5B 候选池是逻辑语料规模，不要求规范化文本、两套 tokenizer 编码、全部图片和解码帧同时常驻本地。缓存可驱逐的前提是内容可按固定 revision/hash 重建；无法重建的唯一原始文件必须保留或先做经过验证的归档。
