# educational-v1 对话训练失败复盘

2026-09-08：以“能正常说话、提供可体验的对话 demo”为目标，本轮失败。
三个模型都能执行训练、保存权重并生成 token，但 SFT 的实际输出仍然重复、偏题，不能将执行完成或 loss 下降记为模型可用。训练预算、数据选取和验收方式是本轮方案的责任。

## 实测证据

重新评估使用完整的 551 条 SFT 留出样本（75,084 个监督 token）和 172 对偏好留出样本；SFT 与 DPO 都在相同的对话留出集上计算 token 加权 NLL。每个检查点另生成四条固定提示的 greedy 回答，记录权重 SHA256，原始输出保留在 JSON 中。固定提示用于人工检查，不冒充标准能力榜单。

| 模型 | SFT 检查点：对话 NLL | DPO 检查点：对话 NLL | 判断 |
|---|---:|---:|---|
| MiniKimi-K3 | 6.868 | 7.462 | SFT 已不连贯；DPO 后语言建模指标退化 |
| MiniDeepSeek-V4 | 6.625 | 7.392 | SFT 已不连贯；DPO 后语言建模指标退化 |
| MiniQwen4 | 6.453 | 8.041 | SFT 已不连贯；DPO greedy 输出退化为连续换行 |

Kimi/DeepSeek/Qwen 全部 172 对偏好验证的 DPO loss 分别为 0.912 / 1.134 / 1.305，偏好 margin 正确率分别为 62.8% / 61.6% / 53.5%。偏好指标与自然对话质量并非同一目标，不能用某一指标覆盖实际生成失败。

证据：[Kimi](audits/minikimik3-capability-v1.json)、[DeepSeek](audits/minideepseekv4-capability-v1.json)、[Qwen](audits/miniqwen4-capability-v1.json)。三个完整对比均已结束，报告包含 `finished_at`。

例如给 Kimi SFT 输入“请解释为什么下雨后地面会湿。”，输出反复重复“意识”与“意识”；Qwen SFT 对“2加3等于几”的回答反复生成不正确的算式。DPO 之前已经存在这些问题，不能把根因全部归于 DPO 或默认采样温度。

## 已确认的方案缺陷

1. **预算不足。** 每个模型基础预训练仅 `1000 × 8 × 255 = 2,040,000` 个预测 token，约为已准备预训练数据的 0.267 轮。Qwen/DeepSeek 另有约 164 万继续预训练 token。SFT 每模型只见到 4,000 条样本，约 0.136 轮；DPO 只见到 800 对。没有足够证据支持在这个预算后自动进入偏好训练并期待可用对话。
2. **原始前缀有题材和模板偏置。** 29,449 条 SFT 训练记录只有 11,865 种首个用户问题；“你今天过得怎么样？”出现 2,230 次，“你如何看待自身存在的目的与意义？”出现 1,006 次，“你如何看待自我意识的边界？”出现 599 次。对源文件取前缀再 shuffle 不会消除这种偏置；整段 JSON 精确去重也不会去掉不同扩展对话中的相同开头。
3. **验证不充分。** 旧管线每 rank 只验证文件开头 4 条，总共 8 条；源文件开头又包含身份类对话，不能代表整个留出集。旧日志中 loss 下降证明优化发生，但不能证明语言能力达标。
4. **过早 DPO，且默认 demo 总选最新阶段。** 没有先对 SFT 生成做验收；最新 DPO 检查点不一定优于 SFT，本次对话 NLL 对比已经出现退化。
5. **容量与样本预算没有协调。** 三个模型词表都是 65,536，单是输入 embedding 和未绑定输出头就有约 6,711 万参数。该词表是否适合新的 mini 配方需要另做实验，不能把缩小层数等同于已经得到合理的训练预算。MiniMind 的小词表取舍可参考其[官方说明](https://github.com/jingyaogong/minimind#ⅰ-tokenizer)。

另外，长度 256 截断了 4,597 / 29,449 条 SFT 训练对话（15.6%）。抽查的 tokenizer 编解码往返、角色边界、assistant 标签和推理前缀能够对齐，但这不排除尚未发现的整模型训练实现问题。

## 已落实的纠正

- 新数据准备默认遍历完整固定 revision 源文件做均匀 reservoir 抽样，记录全文件 hash、原始行数和抽样种子；旧 prefix 方式仅保留为显式选项。尚未用新的抽样方式重建训练产物，旧数据和权重原样保留。
- 验证改为整个留出集上的固定均匀样本，默认每 rank 64 条；`--eval-batches 0` 覆盖完整留出集。额外记录样本数和 DPO preference accuracy。
- 自动训练启动器必须显式指定预训练、SFT 的步数或 epoch 预算，recipe 记录实际覆盖量；移除隐式 1,000/500 步配方，DPO 默认关闭。
- 加入完整检查点评估脚本；训练 `state=complete` 与 `capability_status` 分开记录。生成失败的当前检查点标为 `failed`。
- Demo 默认展示 SFT，提供 SFT/DPO 切换，显示“未通过对话验收”。界面调整不会修复现有权重的能力。

## 尚未完成

当前没有产生可以正常对话的新模型，也尚未启动第二轮长训练。已启动独立的小批量可学习性诊断：从每个模型的 SFT 检查点出发，只拟合 8 个短问答，100 次更新，长度 64；训练和验证故意使用相同数据，只能用于检查记忆和训练/生成链路，不能说明泛化或对话能力。产物位于 `outputs/<model>/memorization-probe-v1/`，运行种类为 `acceptance`，不会出现在 demo。

[Kimi 记忆实验](audits/minikimik3-memorization-v1.json)和 [DeepSeek 记忆实验](audits/minideepseekv4-memorization-v1.json)已完成：8/8 条 greedy 生成与已训练答案完全一致，记忆 NLL 分别降至 0.000448 / 0.000222。Qwen 诊断尚在运行，第 25 步记忆 NLL 为 0.00629，尚未记录最终生成复述结果。这些结果能排查基础学习链路是否完全失效，不能排除其他实现问题或证明泛化。

下一轮仍需重新确定语料覆盖、模板去重、完整回复保留、词表和 token 预算；在基础预训练与 SFT 的留出指标、固定提示和人工阅读都显示可用进展后，再评估是否进入 DPO。不能继续用“跑完所有阶段”作为成功标准。
