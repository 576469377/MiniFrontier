# Batch 边界、实验重排与全仓实验复核

日期：2026-09-10。首批执行快照为 `index.json` 中的时间；后续复核的精确采集时间在 `reviewed-registry.json`。本目录保存数值与决策背景，[当前计划](../current-plan.md)是后续研究的唯一说明入口。

复核快照共 **215 条记录、13 类用途**，没有未归类记录或检测到的活跃输出/GPU 分配冲突。215 包含训练阶段、父扫描和安装 fixture。31 条旧记录缺少 source 身份；4 条缺少数据/tokenizer 身份；1 条历史 RL 接口试验缺少结束证据，保留 `unverified`。这些缺项没有被写成通过。

## 复核范围

台账逐条收集本机与已同步远端的来源模型、MF1、历史训练、离线安装/阶段测试、父扫描和实际训练记录。`reviewed-registry.csv` 提供逐项编号、状态、预算、用途和问题；JSON 保留来源与校验值。记录条数包含父子阶段，不能视为同样数量的独立科学试验。

用途类别覆盖旧语言训练、来源模型可学习性、优化器/LR/MTP、停止的补种子、batch16、吞吐扫描、旧吞吐选择长训、MF1 学习、指令扩展、性能、接口集成及新 batch 控制验证。缺失的旧 source/data/tokenizer 身份如实标记，不补造。硬件与模型能力验收仍独立于执行状态。

性能窗口是 3 次预热 + 8 次真实更新，不含整个作业启动、完整验证和保存成本。合成边界扫描另固定 65,536 input positions/update，因此也不能与较早 16,384 的合成测量直接比较。21 GiB allocator 限制下，DeepSeek 64、Qwen 128 触及边界；Kimi 128 可运行。

Kimi 128 把约 1M CE 的更新数降到 21 次，16 档为 54 次，短测终点 NLL 分别为 9.0761 与 8.0135。32 档为 42 次、NLL 8.2245。这组差异包含实际全局 batch、更新次数和未独立调优 LR 的影响，不能声称是固定全局 batch 的纯性能消融，也不能据此判断长程最优配方。约 8K CE/s 的发现保留为重要执行候选。

MF1 完整 228M、512 长度、20 次预热 + 100 次测量已完成，约 **66.32 CE/s**、peak reserved **6.72 GiB**。其 batch8/16 短筛仍约 68 CE/s，说明单纯放大 batch 未解决 reference 调度瓶颈。其图文真实训练、长上下文和所有后训练阶段需要分别测量，不能直接套用 Kimi 的 batch。

### 固定全局 batch 后的 Kimi 复验

四次运行均已完成，逐 update 的样本位置、实际 input 和全部 token/media 账本完全一致：**16 updates、1,045,978 CE、1,052,262 input、50 次图像暴露**。各档使用本机独立 3090，128 在 GPU 4，16 在 GPU 5；未进行两张物理卡的交叉换位。以下仍是 3 次预热 + 8 次更新的短测和固定 32 例验证。

| 实现 / microbatch 上限 | 固定 input 目标 | CE/s | peak reserved GiB | 终点 NLL |
| --- | ---: | ---: | ---: | ---: |
| 首次有界取样 / 16 | 65,536 | 2,855 | 5.52 | 9.47127 |
| 首次有界取样 / 128 | 65,536 | 4,348 | 19.17 | 9.48141 |
| 完整窗口合批 / 16 | 65,536 | 3,523 | 5.29 | 9.47779 |
| 完整窗口合批 / 128 | 65,536 | 6,772 | 19.17 | 9.47726 |

完整窗口合批先选取整个更新窗口，再按上限合成大微批，避免窗口末端产生多次小样本前后向。首次实现冻结于 `4fada3e`，合批实现冻结于 `dd2b519`。相同新实现中，128 相对 16 的测量吞吐约 **1.92 倍**，两组短测 NLL 接近。这支持保留 128 作为执行上限候选；它不证明固定全局 64K 或从训练开始使用大 batch 是最优配方。旧版约 8K CE/s 使用另一种全局窗口，不能混成同一受控加速比。

原始逐更新数据、配置/命令/来源、窗口一致性和临时权重 hash 清单见 [controlled-batch-comparison.json](controlled-batch-comparison.json)。所有这四项临时权重均按启动前声明的策略清理，日志、数值与恢复文件 hash 保留。

## 处理决定

- 七项旧 microbatch2 运行按用户要求停止，已有日志和恢复点保留。远端六项尚未到保存间隔，没有新 checkpoint；中断时的观测 CE 不能当作可恢复状态。
- 三项本机 batch16、四项已经启动的远端 Kimi128/DeepSeek32 长试验保留为冻结旧源码的探索记录。远端长期队列的后续派发暂停，等待的 Qwen 长试验不继续按旧吞吐选择规则启动。
- 两项 MF1 100K 指令扩展约 2 CE/s，停止为 `stopped_for_review`；已保存的控制和扩展恢复点、最新未保存进度分别记录。先解决性能与实验设计再扩大预算。
- 新源码把 microbatch ceiling 与全局 input 目标分开；新增 CE 节点的 batch ramp，保持完整样本与媒体，记录实际目标/窗口。旧 frozen checkout 不变。
- 取消按“最快 5% 内最小 batch”直接晋级长期训练的规则。该选择仅用于最多 1M CE 的执行确认，后续配方需要显式的全局 batch/LR/质量计划。
- DeepSeek 路由的 Muon 与 AdamW 实际共用 `--lr`。旧命令中的 `--muon-lr 0.01` 没有被该优化器使用；reference 实际均为 3e-4，低 LR 对照均为 1e-4。以源码构造器和实际参数组为准，旧数值记录保留原样，解释在本次复核中修正。

| 文件 | 内容 |
| --- | --- |

数据、图片、tokenizer 文件和权重不在本目录。路径统一替换为 `${WORKSPACE}`，进程、设备 UUID 和容器标识从公开副本移除。历史数值只证明记录中的配置和时间窗口，不证明正式训练、能力准入或外部逐字节数据重建已经完成。

队列中的输入 hash 指向运行时原始文件；路径归一后的公开副本可能具有不同的字节校验值。复现时先绑定工作目录并核对记录的源码、原始数据及 tokenizer 身份，不能把公开副本的 hash 当成原始文件的 hash。
