# MF1 执行性能审计（2026-09-10）

MF1 的旧实现存在明显的执行瓶颈，也存在一处单 token KDA 训练梯度缺失问题。本次完成了代码修复、独立数值对照、CUDA 验证和单卡性能测量。结果支持继续开展正式数据上的资源验收；尚不构成正式预训练、学习曲线或对话能力验收。

[数值档案](minifrontier1-execution-performance.json) 保存源码身份、配置、命令参数、逐步耗时、梯度范数、显存、验证结果及校验值。原始样本、权重和机器标识不随该档案分发。

## 瓶颈与修复

| 位置 | 检查发现 | 本次处理 |
| --- | --- | --- |
| [CSA](../../minifrontier/models/minifrontier1/csa.py)、[QSA-MLA](../../minifrontier/models/minifrontier1/qsa_mla.py) | 对每个 query 执行 Python 循环、小矩阵乘法和动态索引；MTP 的注意力也受影响 | 按有界 query chunk 合并计算；稀疏支持集仍保留全部被选择的 token |
| CSA 压缩器 | 每个四 token 块分别建索引、门控池化 | 向量化块成员与 overlap 池化，保留 segment／媒体边界和短块完成时刻 |
| [KDA](../../minifrontier/models/minifrontier1/kda.py) | 独立样本被拆成多个 B=1 调用 | 将等长独立片段合批执行；卷积与递归状态在 packed 边界重置 |
| [LatentMoE](../../minifrontier/models/minifrontier1/moe.py) | 每个专家单独查找 token 并执行小 GEMM | CUDA 使用已有的分组投影工具；保留路由、加权顺序和 FP32 聚合，偏载时回退，不丢 token |
| [训练循环](../../minifrontier/training/minifrontier1.py) | `input_batch_tokens` 只扩大逐样本累积窗口，没有真实的行合批 | 新增 `--batch-size`，默认最多 8 行；先固定全局样本窗口，再按行数和 padding 后 token 容量合批 |
| 梯度检查点 | 每层将 query 计数转成 GPU tensor 后再读回 CPU | 直接返回整数，去掉这次往返 |

128-token 基线更新的 profiler 记录了 31,643 次 `aten::copy_`、6,269 次 `aten::bmm` 和 2,273 次 `aten::nonzero`。执行优化版本的复制调用降至 9,848 次，`nonzero` 降至 649 次。原始前 30 项算子表保存在数值档案中；这些调用包括前向、反向、重计算和优化器，不能用 profiler 的 CPU／CUDA 时间总和直接推算 GPU 利用率。

数据读取也做了独立检查：相同前两个采样窗口的记录校验、tokenization 和媒体预处理，在文件系统缓存已热的情况下分别耗时约 0.041 秒、0.008 秒。本组小数据的每步几十秒耗时主要来自模型执行；该测量不包含 H2D，也不代表大规模媒体数据的冷读性能。

## 正确性问题

旧 KDA 适配器会让单 token 训练片段进入只有前向计算的 FLA recurrent 路径。CUDA 复现中，`q_proj`、`k_proj`、`v_proj`、`b_proj` 的梯度均为 `None`。现在只在无梯度的单 token 推理中使用该路径，训练使用支持反向传播的 chunk 路径。回归要求上述投影梯度存在、有限且非零。影响条件是单 token 片段；不能据此推断所有历史训练都没有 KDA 梯度。

合批引入的两个边界也已修正：

- 索引器均匀教师采样只计算有效 query，增加右侧 padding 不改变原样本的采样位置。
- padding 不参与专家计算，未接收有效 token 的专家继续保持 `grad=None`。这会影响 AdamW 的权重衰减和状态更新，不能用零梯度替代。

合批不改变已选样本窗口、CE／MTP 分母、媒体位置和曝光数。P2 仍按原始 packed 行预先选择注意力阶段，只合并阶段相同的相邻行。路由均衡统计继续排除 padding，并排除梯度重计算产生的重复统计。

## 单卡测量

配置均为 [228M 原生配置](../../configs/minifrontier1/model_228m_native.json)，共 228,235,809 个参数，启用 BF16、梯度检查点、AdamW、路由均衡和 MTP（系数 0.1），使用 RTX 3090 24 GiB，每张物理 GPU 只运行一个项目任务。软件为 PyTorch 2.13.0+cu130、CUDA 13.0，CPU 线程数为 2。其他 GPU 可运行独立任务，未把整台主机视为独占机器。

| 固定输入的合成文本短测 | 基线 CE token/s | 执行优化 CE token/s | 比值 |
| --- | ---: | ---: | ---: |
| 1×128 | 31.54 | 108.63 | 3.44× |
| 1×512 | 60.50 | 527.02 | 8.71× |

每行前后使用同一张物理卡、相同 seed 和 token 预算。只运行了 2 次预热、4 次更新；128-token 的 profiler 更新从吞吐计算中排除。这两行用于定位代码开销，不能作为正式长期吞吐承诺。

最终版本另外完成 **20 次预热＋100 次无 profiler 更新**：8×512、每次更新 4,096 输入 token／4,088 CE token，测得 **1,960.91 CE token/s**，显存预留峰值 **6.71 GiB**。该结果包含前向、MTP、反向、梯度裁剪、AdamW 和路由均衡；不包含数据准备、评估与保存。它是随机合成文本的持续测量，不能与上表不同全局预算直接计算加速比，也不能替代原生多模态阶段验收。

真实数据对照复用了[已有指令诊断数据及重建说明](../experiments/mf1-language-performance-v1/README.md)，使用同一初始化检查点、seed=42、语言／图像／视频 CE 混合权重 0.90／0.075／0.025，均执行 2 次更新。下表取第二步，避免将首次执行开销混入比较：

| 运行 | 最大行数 | 实际微批次数 | 第二步耗时 | 输入 token/s | CE token/s |
| --- | ---: | ---: | ---: | ---: | ---: |
| 基线 | 1 | 28 | 49.98 秒 | 10.36 | 1.86 |
| 执行优化 | 1 | 28 | 21.48 秒 | 24.11 | 4.33 |
| 执行优化＋合批 | 8 | 4 | 6.00 秒 | 86.28 | 15.49 |
| 最终修复复测 | 8 | 4 | 5.43 秒 | 95.44 | 17.13 |

前三行在同一物理卡执行，第二步约加速 8.3 倍；最后一行在另一张同型号卡上复测，因此不将它相对第三行的差异归因于代码改动。每步 28 条样本的合批形状为 8／8／8／4，第二步包含 518 输入 token、93 CE token。

四个运行结束后的采样器状态 SHA256 和完整 token 账本一致：共 1,037 输入 token、192 CE token、80 MTP target、81 视觉 token、7 次媒体曝光。数值档案保留两步指标和完整验证结果。BF16 合批会改变矩阵乘法的舍入，路由边界也可能随之改变；没有宣称权重或学习曲线逐位相同。真实数据只运行了两步，所有产物都仍是 `budget_complete_unqualified`。

## 回归与后续边界

- 全仓 CPU：349 项通过、1 项跳过；跳过原因是 Qwen 未声明原生 MX QAT 配方。
- 新增 CUDA：8 项通过，包含 KDA 单 token 梯度、BF16 QSA／专家前向及梯度对照，以及图像／视频在 dense 和 sparse 路径的缓存续算、回滚。
- CPU 独立 oracle 覆盖 overlap 池化、逐 query 注意力、packed KDA 输出／梯度／状态，以及 padding、CE、MTP、索引器归一化和未激活专家的 AdamW 更新。
- CUDA 注意力与专家梯度对照满足相对 L2 误差小于 3%、余弦相似度大于 0.999；CPU 浮点对照采用更严格容差。具体断言见 [执行回归](../../tests/test_mf1_execution.py)。
- Ruff、格式检查、Mypy 通过；上游源码映射的 24 个文件校验值全部匹配。

执行仍有改进空间：注意力保留按行循环和有界支持集构造；KDA 对不等长 packed 片段仍需分组；路由统计和优化器仍有小算子开销。当前 native `RecordDataset` 会重复校验和编码，正式长度采样初始化还会扫描并编码样本，扩大到大数据前需要接入或验收预编码索引的启动成本。

本次没有证明 batch=8 最优，也没有依据将其他模型的 batch=128 直接复制到 MF1。后续应在准备好的正式数据、实际 context／媒体预算和既定全局 token 预算下，完成一次有界资源验收，再进入阶段训练；保留既有的能力和数据准入门槛。

四组真实数据对照已接入本地 TensorBoard 的 `mf1-execution/`，使用统一的 `train`／`perf` 标签；最终验证指标保留在报告中。数值档案可直接重画每步曲线。三个中间诊断检查点在完成采样器／账本比对并记录校验值后已回收，释放约 12.75 GiB；保留最终修复检查点及共享初始化权重。全部审计任务已结束，没有自动续接旧的小 batch 学习实验。
